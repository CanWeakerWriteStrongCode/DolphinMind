# BaijiMind v0.1 实现计划（单 Java 模块化单体 · 可集群部署）

> 对应开源项目：domain-separated-self-boot-agent-runtime
> 计划版本：v0.1 第一版 · 文档日期：2026-08-21
> 依赖范式白皮书：[docs/original-2026-paradigm.md](original-2026-paradigm.md) · 关键决策记录：[docs/v0.1-key-decisions.md](v0.1-key-decisions.md)

## Context

把白皮书范式落成第一个可运行版本。方向经确认——**单 Java 模块化单体，可集群部署（横向扩容）**，最适合中小企业落地。

- **Java = 全部业务**：认证/RBAC/组织树/项目需求/内容空间权限/审批/版本/审计/密钥/通知 + 流程编排 + 对话式命令路由 + **IM 网关（适配器架构，借鉴 AstrBot；v0.1 飞书实现）** + RAG（Spring AI/Tika/Milvus）+ AI Agent 执行循环 + harness 工具 + Git 操作（LangChain4j/Spring AI）
- **不做**：Go 服务、gRPC、插件注册中心（Go 归属）——砍掉的只是跨进程分布式复杂度
- **容器沙箱（代码制度）**：AI 产物 = **真实代码（Go 工具 / 工作流 / 业务组件）→ 构建容器镜像 → 审批 → 容器沙箱启停**（docker-java 管理；开发/测试环境 KVM 虚拟机，生产 Docker 容器——对齐行业惯例）

**自举的定义（对齐用户愿景）**：AI 在协作执行中发现可复用能力 → 写**真实代码**（Go 工具/工作流/业务组件）→ 构建容器镜像 → 审批 + 版本注册（镜像 tag）→ 容器沙箱运行生效 → 固化进系统（代码制度）。工具分两种：**工具型**（function-calling 契约，agent 经 HTTP 调用容器插件）与**业务型/事件驱动**（订阅 RocketMQ 领域事件自主运行的容器插件，Java 事件驱动宿主）。**发现多通道**：即时（agent 协作中主动提议）+ 周期（自举观察器定时组织审计）+ harness 工具自省（判断是否需要新版本）。

约束：不要太复杂，docker-compose 一键起，最小 Vue3 控制台，AI 统一走 OpenAI 兼容 API。

## 关键流程（含各流程注意点）

**1. 任务闭环**
人（前端/IM）经 Java 创建 `exec_task=CREATED` → Java worker 原子领取（=CLAIMED, owner, claim_at+deadline）→ Agent 进程内取 RAG 上下文 → harness 工具执行（内置原生；AI 新工具经审批注册后直接调用）→ 产出制品（MinIO）/推 feature 分支 → **独立评估者按可测完成条件判定达成**（只读制品 / 测试 / 边界报告，执行者不自报 DONE，生成/评估分离，见 §6.4）→ 置 DONE + 回传总结 → Java 通知（站内 + 直发飞书）→ 人审批合并。全程 event+audit：任务状态变更（task.created/claimed/completed/expired 等）发布领域事件到 **RocketMQ 事件总线**，notify / eval / cost / flow / observer 订阅联动；事件发布与业务落库同事务（事务性发件箱，见决策 20）。

- **注意点**：领取/状态迁移用单行条件 UPDATE（status=?）防并发双领；CLAIMED 带 deadline，超时回收重置，避免死任务；执行幂等可重入（制品覆盖写+唯一键）；全程按授权人作用域（决策13）经内容访问接口读数据（决策15）；git 只推 feature 分支，不碰主分支/生产；事件消费方幂等（eventId 去重、可重放），防重复通知/重复评估。

**2. RAG 构建与检索**
**事件触发 + @Scheduled 兜底**：文档新增/更新与 IM 消息归档发布领域事件（space.doc.created/updated、im.msg.archived）→ 事件触发增量构建；@Scheduled 周期兜底拉取防漏 → Tika 解析 → 结构化切块 → embedding（OpenAI 兼容 API）→ 写 Milvus（project_id 分区 + 权限元数据）；检索：Milvus 混合检索（dense+BM25+RRF）+ 分区裁剪权限过滤 → top-k → 可选重排 → 拼 context。AI agent 与前端都走同一进程内检索。

- **注意点**：增量用游标/时间戳去重，防重复索引；切块 512-1024 token + 128 overlap，聊天文本按时间窗口切；元数据（项目/需求/权限域）必须带上、检索前过滤；权限过滤在 index 层（分区裁剪），不后置过滤；embedding 模型选定后版本化，换模型需全量重建。

**3. AI 自举审批版本化**
AI 提交新**容器插件**/新流程 → Java 建 `boot_approval(PENDING)` + 版本草稿（含 contract_schema + artifactRef 镜像引用 + event_subscriptions）→ 通知审批人 → 审批通过 → 版本 ACTIVE → 容器沙箱启停生效 → 按 capabilityKey 发现、按契约 function-calling 生效（经 HTTP 调用容器插件）→ 回滚旧版本。

- **注意点**：版本状态机（DRAFT（KVM 试运行）/ TEST（Docker 测试）/ ACTIVE（生产）/ INACTIVE / REJECTED）单调迁移，禁止跳变；契约与事件订阅随版本不可变；热升级失败自动回退旧版；注册表即 `boot_plugin_version`（无独立运行态，Java 单进程）。

**4. AI 自举闭环（发现→开发态试运行→晋升审批）**
发现（即时 agent 提议 / 周期观察器报告）→ `propose_plugin` 起草 DRAFT → 写真实代码（Go）→ **KVM 试运行**（开发态迭代，受限资源、无凭据、不接触生产）→ 构建容器镜像 → **Docker 测试**（测试态验证，贴近生产形态）→ 满意提交审批 → 审批通过 → 版本 ACTIVE **上生产** → 运行时订阅 **RocketMQ 领域事件**自主运行（Java 事件驱动宿主）→ 产出回 Java 域 → 回滚旧版本。

- **注意点**：DRAFT 试运行只碰受限测试资源、无凭据（决策15）、不接触生产；"即写即执行"的自由以受限边界为限；晋升必须审批+版本；事件订阅命中范围按项目/权限域受限，防工具越权接事件。

**5. harness 工具自省（二期闭环，v0.1 仅留口子）**
agent 调用工具 → 机械信号落 exec_task_event（v0.1）→ 二期周期聚合总体审视 → LLM 判断"某 harness 工具需不需要新版本" → 版本升级提案 → 审批 → 新版本 → 热升级 → 可回滚。

- **注意点**：v0.1 只落数据口子（重试/错误/耗时 + 预留 tool_feedback 字段），不实现分析；二期直接复用审批/版本管线，无需新机制。

**6. 会话驱动工作流闭环（IM 场景主线）**
管理员建群+绑项目/需求+配机器人+绑流程 → 产品/开发/测试在群里与 AI 协作（消息落内容空间）→ 人 @AI 指令（如"开始写 PRD"）→ 命令路由 LLM 解析 →（决策点）管理端需求流程页审批（群里发链接跳转，类似 OA）→ 推进 → 建 exec_task（授权人=点击者，决策13）入任务队列 → AI 领取并以授权人数据权限执行（写 PRD/gen_h5_prototype 画 H5/写代码）→ 产物入内容空间 → 产品 IDE 改 → 人 @AI"进入下一流程"（或流程页操作）→ 流程引擎推进 → 后续阶段 AI 出设计图 → 明确"写代码" → agent harness 写代码推 feature 分支 → 人 IDE 改推送 → 测试 → 交付通知。全程 im_command 落账 + 领域事件走 RocketMQ 事件总线 + audit_log 审计（可重放）。

- **注意点**：@AI 指令需二次确认（管理端流程页审批），防误触；授权人=点击者/指令发送者，数据权限全链路贯穿（决策13/15）；意图解析失败降级为"回复提示无法理解"，不静默；群里只发管理端链接，流程决策在管理端完成；im_command 全程落账可追溯。

## 总体架构（docker-compose 拓扑）

```
Browser ──HTTPS──> Nginx(单入口) ──/api──> java-server:8080 (Sa-Token 校验 + 全部业务/编排/执行/RAG/IM)
IM 平台(飞书 v0.1) ──长连接/Webhook──> java-server:8080 (IM 网关适配器：IMProvider + ImMessage 统一模型)
java-server ──→ Milvus:19530 (向量检索, Standalone)
java-server ──→ RocketMQ namesrv+broker (领域事件总线：跨模块事件驱动 + 重放/审计)
java-server: MySQL(全部表) · Redis(Sa-Token/会话/分布式锁/缓存) · MinIO(文档+制品) · SSH密钥(AES-GCM存库)
```

> 单 Java 服务；多实例部署时各实例共享 MySQL/Redis/MinIO/Milvus/RocketMQ，会话入 Redis 无状态化，分布式锁防重复调度；RocketMQ 消费组天然支持多实例水平消费。

## 关键技术决策

详见 [docs/v0.1-key-decisions.md](v0.1-key-decisions.md)，此处为摘要：

1. **单 Java 模块化单体**：一个进程一个部署，内部按未来微服务边界切模块（模块化单体，跨模块只经接口）；不引入 Spring Cloud/Nacos/Gateway。
2. **IM 网关 = 适配器架构（借鉴 AstrBot）**：`IMProvider` 接口 + `ImMessage` 统一消息模型（platform/channel/sender/content/attachments）+ 适配器注册表；各平台适配器把原生消息/协议/认证归一成统一结构，核心逻辑（命令路由/归档/RAG/事件发布）平台无关。**v0.1 仅飞书实现**（官方 Java SDK 长连接收事件 + 开放 API 发消息），QQ/企业微信/钉钉 适配器二期填。不做交互卡片，流程决策走管理端需求流程页（类似 OA）。
3. **数据库 Java 全 owner**：全部表（含 msg_archive 聊天归档）Java 管。`deploy/sql/schema.sql` 一份 DDL + 表所有权清单。
4. **任务队列**：`exec_task` 表 + 原子领取乐观锁（DB 行仍是事实源，CQRS-lite），`claim_at+deadline` 超时回收，幂等可重入。队列本身不引入 MQ（原子领取语义）；**跨模块事件总线见决策 20（RocketMQ）**。
5. **向量检索 = Milvus（Standalone）**：混合检索（dense+BM25+RRF）；`project_id` 作 partition key，权限过滤按分区裁剪；重排留接口。
6. **切块策略**：结构化切块（Tika + LangChain4j），512-1024 token + 128 overlap；聊天按时间窗口切。
7. **流程编排 + 执行都在 Java**：JSON DAG 定义/审批/绑定/走查/执行一体。
8. **AI Agent + harness 在 Java**：LangChain4j/Spring AI function-calling；AI 新工具经审批注册生效；工具调用落机械信号。
9. **AI 产物 = 容器插件（代码制度，Docker 容器沙箱）**：AI 写真实代码（Go 工具 / 工作流 / 业务组件）→ **环境晋升链：先 KVM 测试、再 Docker 测试、最后上生产**——开发态在 KVM 虚拟机试运行迭代（写码-试错、最快反馈），Go 标准工具链构建**容器镜像**（多阶段 Dockerfile）后进 **Docker 测试环境**验证（贴近生产形态，docker-java 沙箱：资源上限 `--memory/--cpus`、超时熔断、无凭据、网络受限、只读根），测试通过经审批晋升后才在**生产环境**的容器运行，全程可回滚。需硬件级隔离时可上 **Kata Containers**（KVM 背衬容器）。Java ↔ 插件走 HTTP（内网）/ sidecar 跨进程调用，而非进程内函数调用。**砍掉 WASM/TinyGo/Extism 整链**——不再受 WASM 子集限制、不依赖小众工具链；隔离由操作系统容器提供（namespaces + cgroups + seccomp），比进程内沙箱更强。
10. **密钥加密**：ssh key/IM secret/LLM key/Milvus key 落 `sec_secret`，AES-GCM 密文，明文不进库。
11. **多企业预留**：核心表带 `enterprise_id`。
12. **组织可观测性（留口子）**：直接聚合现有表出组织快照，独立可观测层二期。
13. **授权即边界（数据权限委托）**：`exec_task.authorizer_user_id` 记录授权人，AI 全链路（RAG/内容空间/git/IM）限定在授权人作用域，越权拒绝并审计。
14. **越权审计（留口子）**：控制台"越权审计"页（人审）+ 观察器聚合越权统计（AI 审）；深度合规分析二期。
15. **接口即边界**：AI 不直连 Mapper/表，企业内容读取一律经带权限的「内容访问接口」。
16. **定时任务 = Spring @Scheduled + Redis 分布式锁**：RAG 增量构建、任务超时回收、自举观察器周期审计统一用 `@Scheduled`，配 Redis 分布式锁（Redisson RLock，Redis 已存在、零新增中间件）保证多实例只有一个执行，不引入 Quartz/xxl-job/PowerJob 等调度中间件。
17. **SSO / OAuth2 企业登录**：企业微信 / 钉钉 / Azure AD，进 module/auth。
18. **LLM 成本与用量**：模型路由 / key 池 / token 统计 / 成本报表（infra/llm + module/cost），企业落地刚需。
19. **集群部署（可横向扩容）**：无状态化（Sa-Token 会话入 Redis）+ Redis 分布式锁 + 共享存储（MySQL/MinIO/Milvus/RocketMQ）；v0.1 单实例可跑，二期上 K8s 横向扩容。
20. **事件驱动 + CQRS-lite（RocketMQ 事件总线）**：模块间通知型/联动型协作走领域事件——任务生命周期、流程节点、IM 消息命中、文档新增、审批、工具调用、LLM 用量等经 **RocketMQ** 发布/订阅；命令写走领域模块接口（DB 为事实源）；**v0.1 读写同一张表、不做异步投影**，读侧走**内容访问接口**（低层同步读取保留直接 Query，决策 15）；**读模型/异步投影留待后续按需演进**（事件已就位，届时直接加投影、不改机制）。**不事件溯源**。发布走**事务性发件箱**（业务表与 `event_outbox` 同事务 → @Scheduled 轮询投递 RocketMQ，Redis 锁防重复，复用决策 16），消费方**幂等**（eventId 去重、可重放）。RocketMQ 的持久化/重放能力即重放日志与审计的载体（白皮书 §3.1.5 补救经济性）。

## 事件驱动 + 事务性发件箱（模块间解耦方式）

模块间交互分两条路径：

- **命令/查询接口（同步，保留）**：写侧命令（Command API，含事务与返回值的场景：任务领取、审批、流程推进的状态机迁移）与读侧查询（Query API）。**低层同步读取保留直接 service 调用**——① 内容访问接口（AI 读企业内容的权限读通道，决策 15）；② RAG 检索（agent 进程内同步取上下文）；③ 权限/授权人作用域校验；④ 流程推进需同步读当前节点状态。
- **领域事件（异步，RocketMQ）**：模块间「通知型/联动型」协作走事件；发布方与业务落库同事务（事务性发件箱），消费方幂等。

**事件目录（v0.1 全集）**：

| 事件 | 发布方 | 订阅方 |
|---|---|---|
| task.created / claimed / completed / expired / evaluated | task | notify / eval / cost / flow / observer |
| flow.node.entered / advanced / completed | flow | notify / 业务型工具 / observer |
| im.msg.archived（IM 群消息命中） | im | cmd（命令路由）/ rag（增量构建）/ 业务型工具 |
| space.doc.created / updated（文档新增/更新） | space | rag / observer |
| boot.approval.created / passed / rejected、boot.plugin.version.* | boot | notify / observer / 工具宿主 |
| tool.invoked（工具调用机械信号） | harness | task（落 exec_task_event）/ cost / observer |
| llm.usage（LLM 用量） | infra/llm | cost |

**Topic/Tag 约定**：Topic=领域（`baimind-task` / `baimind-flow` / `baimind-im` / `baimind-space` / `baimind-boot` / `baimind-tool` / `baimind-llm`），Tag=事件类型（如 `task.completed`）；消费组按模块建（一模块一 ConsumerGroup，天然支持水平消费）。事件体带 eventId + 幂等键 + 时间戳。

**读写同表，异步投影留待后续**：v0.1 **不做读模型/投影**——事件只做模块间消息机制，各模块读写同一张表（读侧经内容访问接口，见决策 15）。**以后**需要读解耦/读性能时，事件已就位，按需为任务看板、流程状态、组织快照等加**异步投影（读模型）**即可，不改事件机制本身。

**可靠性**：事务性发件箱（`event_outbox` 表 + @Scheduled 轮询投递，Redis 锁防重复，复用决策 16 模式）保证「业务落库与事件发布同事务」；消费幂等（eventId 去重）；RocketMQ 持久化即可**重放**——重放日志既是补救机制（白皮书 §3.1.5 压 ρ），也是观察器/越权审计的数据源。

## AI 自举（受控）：协作中发现 → 开发态试运行 → 晋升审批

- **发现（多通道，v0.1 均最小实验）**：① **即时发现**——agent 干活中识别可复用模式 → `propose_plugin` 起草 DRAFT；② **周期发现——自举观察器**——定时聚合现有任务/流程/工具/审计数据 + 内容空间 RAG，输出观察报告 + 候选工具提案 → 审核转 DRAFT。**留口子**：观察器只做最简实现（@Scheduled + 一次 LLM 归纳 + observer_report 落库）。
- **harness 工具自省（留口子）**：v0.1 只落数据口子——工具调用机械信号记入 `exec_task_event`，预留 `tool_feedback` 字段；完整审视/版本升级提案放二期，复用审批/版本管线。
- **宪法式 AI 预审自检（留口子）**：预留「AI 依据中心原则（宪法）自检」的前瞻位置（中心原则=宪法，见 §3.2.4）；宪法式 AI 成熟后再启用，兜底仍是审批与治理锚点。
- **开发态试运行（自举的自由）**：DRAFT 插件先经 **KVM 试运行**（开发态迭代），构建镜像后进 **Docker 测试**（测试态验证），只碰受限资源、无凭据、不接触生产。
- **晋升（自举的受控）**：试运行满意 → 审批（boot_approval）→ 版本 ACTIVE → 注册生效 → 接收真实业务/IM 事件流量；回滚走版本回退。全程 audit_log。
- **业务型工具（事件驱动宿主）**：声明 `events` 订阅（IM 群消息命中、task 状态变更、flow 节点进入、文档新增）→ Java 域将领域事件发布到 **RocketMQ 事件总线** → 事件宿主订阅分发 → 工具执行并回发动作（订阅命中范围按项目/权限域受限，防越权接事件）。工具型工具走 function-calling 契约。

## 关键注意点（风险清单）

- **并发安全**：任务领取/状态迁移必须单行条件 UPDATE（status=? 乐观锁）；执行幂等可重入。
- **集群无状态化**：多实例部署时 Sa-Token 会话必须入 Redis；定时任务用 Redis 分布式锁防重复执行；不引入单实例内存态强依赖。
- **权限不可绕过**：AI 读企业内容只经「内容访问接口」，禁止注入 Mapper/直连表。
- **容器沙箱边界**：AI 生成的容器插件只在沙箱内执行（cgroups 资源上限 + 超时熔断 + 无凭据 + 网络受限），不注入生产凭据；插件内读企业数据仍须经内容访问接口（决策15）。
- **密钥安全**：ssh key/im secret/llm key 只存 sec_secret 密文（AES-GCM），明文不进库。
- **超时回收**：CLAIMED 带 claim_at+deadline，超时回收重置，避免死任务。
- **本地 dev 无公网**：飞书用长连接收事件；流程决策走管理端页面（无需公网回调）。
- **多企业预留**：核心表带 enterprise_id，v0.1 单企业部署但结构预留。
- **Milvus 运维权重**：Standalone 单机可跑，资源占用比 Qdrant 高，规模大了再上分布式。
- **LLM 可靠性**：AI 调用统一经 infra/llm 封装（重试/限流/降级），防第三方 API 抖动打挂主链路。
