# 最小自我证明 PoC：「自举工厂」受控自举小游戏

> 目标：用一个「特别小、1 个文件」的代码，**自我证明**本架构核心主张——AI 能不断迭代、自组织、自我重新编排自己的工作链路，且人在环中全程可控。
> 核心设计观：**把「受控自举流程本身」做成游戏**——玩家 = 厂长（治理锚点、人在环中），AI = 提案机器，生产流水线 = 工作链路（生产关系），审批决定速度/质量/成本的权衡与系统兴衰。
> 独立于 v0.1 实现计划的概念自我证明，不进入产品代码路径。

## 交付物

- `poc/self_boot_factory.html` —— **唯一源代码文件**：单文件 HTML+JS（内嵌 CSS+JS），无 CDN、无框架、无构建，双击浏览器即开，离线可跑
- 状态固化于 `localStorage`（刷新可续跑、可回滚）——无第二个源码文件
- **假 AI 演示**（MockAI + MockEvaluator）：无 Key、零配置也能跑，证明的是流程闭环而非模型能力

## 设计原理

- **工序链 = 工作链路 = 生产关系**（协作与分工方式）；AI 重排工序 = 自我重新编排
- **工具 / 工位 / 标准 = AI 可自举的资产**（受审批约束）
- **产出速度 × 合格率 = 生产力**；预算 / 复杂度 = 约束
- **「又快又好」= 速度与质量的双目标权衡**——审批决策的难点与游戏性
- **启发式 → 模式库** = AI 自我启发式积累的显式化（贴白皮书 §3.2.3 模式库）
- **生成/评估分离 = 抄 /goal**：干活者不能自评，独立评估者判（贴白皮书 §6.4 目标与评估）

## 演示剧本（默认 3 轮，可续跑；每轮产出命名启发式进模式库）加质检→质量升速度降；并行/自动检测→提速度
- **合格率** = f(质检覆盖, 质量标准, 无质检时出库漏缺陷)；次品 = 产出 × (1 − 合格率)
- **收入** = 合格品×单价 − 次品×返工 − 维护；预算累计（改造花钱 → 约束）
- **复杂度** → 事故风险（工具越多越逼近失控底线；可触发停机/批量次品）
- **胜负**：连续 K 轮 合格率 ≥95% 且 产出 ≥ 阈值 且 预算 > 0 → **达成「又快又好」**；次品爆仓 / 预算耗尽 / 复杂度失控 / 轮数耗尽 → 失败

## 每轮闭环（架构流程 = 游戏流程）

1. **生产**：AI 按当前工序链跑一轮 → 产出 / 合格率 / 预算 / 复杂度（流水线动画演示）
2. **边界报告**：AI 报告现场缺陷（「包装前无质检，次品直接出库」「质检成瓶颈拖慢全链」）
3. **启发式提案**：AI **先从模式库检索**相关既有启发式 → 结合边界报告生成新启发式提案——①加工位/工具 ②**重排工序链** ③改标准，每条标注经验法则（如「发货前必须过质检」「瓶颈工序可并行化」）
4. **独立评估**：评估者（与提案者分离的 MockEvaluator）对照目标「又快又好」逐条判：采纳 / 驳回 / 有条件 + 理由——干活者不能自评（生成/评估分离）
5. **自动验证**：小样试跑，显示「改后预览」对比，拦住坏提案（机械 ground truth）
6. **人在环中审批**：每个提案独立「批准 / 驳回」按钮（放行耗改造预算，驳

- **R1 朴素线**：`[组装 → 包装 → 发货]` 无质检 → 快、合格率低、次品爆 → 边界报告「发货前无质检」→ 启发式提案「**出库必检：发货前必须经过质检**」→ 加「质检」+ 重排为 `[组装 → 质检 → 包装 → 发货]`
- **R2**：质量上去了、质检成瓶颈拖慢 → 边界报告「快与好不可兼得」→ 启发式提案「**瓶颈并行化：瓶颈工序拆并行提吞吐**」→ 加「并行质检」/「自动检测工具」→ 固化 → **又快又好达成**
- **R3**：已达目标，演示权衡——启发式提案「**原料不检→批量次品**」（原料检验，防批量）vs 复杂度上升风险（失控底线），由玩家抉择

## 页面布局（单文件内）

- **顶部指标栏**：版本 / 轮次 / 预算 / 产出速度 / 合格率 / 复杂度
- **中部流水线**：工序色块 + 产品动画，质检站拦截次品
- **提案面板**：边界报告 + 模式库检索引用 + 启发式提案列表 + **独立评估意见**（评估者判定/理由）+ 「改后预览」+ 每个提案「批准/驳回」按钮（可覆盖评估者建议）
- **模式库面板**：已固化启发式列表（来源轮次/版本，随轮递增）
- **指标曲线**：canvas 折线（产出 / 合格率 / 复杂度 / 预算 逐轮）
- **审计历史**：每轮提案与审批结果，版本化可回滚
- **控制**：开始下一轮 / 自动演示（全批准连跑）/ 重置 / 回滚上一版本

## 技术要点

- 纯手写 ES 语法，无构建工具；canvas 手绘曲线，无 CDN
- `MockAI.work / MockAI.propose`（生成者）+ `MockEvaluator.judge`（评估者，与提案者分离的独立函数）：确定性剧本；两者均注释注明**换真 LLM 的替换点**（评估者对应 /goal 的独立小模型）
- `loadState()/saveState()`：localStorage（含版本历史数组与模式库，支持回滚）；读写包 try/catch，失败降级内存态
- **file:// 存储域**：本地双击打开的页面 origin 为 null，浏览器按「文件完整路径」划分存储域——复制/移动文件到新路径会换桶（旧进度"消失"）；个别浏览器会禁用 file:// 的 localStorage。建议 `python -m http.server` 起本地服务获得稳定 `http://localhost` 存储域

## 验证方式

1. 双击打开 `poc/self_boot_factory.html` 交互 3 轮：看到完整闭环「生产动画→边界报告→模式库检索→启发式提案→独立评估→改后预览→审批→固化」，R1→R2 真实呈现「速度降、质量升」权衡，R2→R3 达成又快又好
2. **模式库随轮递增**：R1 后含「出库必检」、R2 后含「瓶颈并行化」；R2 提案前显示检索到 R1 的启发式引用
3. **生成/评估分离可见**：每个提案先显示独立评估意见（评估者与提案者分离），可采纳或覆盖评估者建议
4. 驳回某提案 → 审计记录「未采纳」，且该启发式不进模式库
5. 「自动演示」按钮无人值守全通过；「回滚上一版本」→ 模式库同步回退
6. 全程驳回 → 停滞警告；全程放行 → 复杂度事故风险可见
7. 无网络环境下打开 → 全部功能正常（零依赖验证）
